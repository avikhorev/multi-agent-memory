# Решения

Решения по дизайну и эксперименту. Каждое записано с причиной и ссылкой на данные. Новые решения добавляются в конец.

## D1. Версия CLI закреплена: 2.1.316

Версия 2.1.316 проверена пилотом и доступна в реестре пакетов. В образе Docker ставится `@anthropic-ai/claude-code@2.1.316`. В окружение дочернего процесса добавляется `DISABLE_AUTOUPDATER=1`. Раннер перед стартом сверяет вывод `claude --version` с закреплённой версией и останавливается с понятной ошибкой при расхождении. Версия пишется в манифест каждой единицы работы. Данные: `docs/PILOT.md`.

## D2. Итоговый набор флагов вызова и политика мышления

Набор флагов и белый список окружения перечислены в `docs/PILOT.md`. Используется только `--effort low`, самая низкая документированная настройка. Мышление отключить не удалось: скрытый флаг `--thinking disabled` и переменная `CLAUDE_CODE_DISABLE_THINKING` не уменьшили число токенов мышления (`results/pilot/thinking.jsonl`: 331 и 365 против 319 по умолчанию). Недокументированные настройки в итоговых флагах не используются.

Следствие для прогноза: на вызов приходится 660–970 выходных токенов, а не 150, как закладывалось в плане. Они включены в оценку стоимости и времени (`docs/PILOT.md`).

## D3. Окружение дочернего процесса по белому списку

Дочерний процесс получает только переменные из белого списка (`docs/PILOT.md`). Причина: при полном окружении родителя служебных токенов 1 326 против 558, а вызов 6,1 с против 2,3 с (`results/pilot/env.jsonl`), и поведение зависит от машины. Значения переменных не читаются и не печатаются. Авторизация со строгим белым списком проходит.

## D4. Офлайн-счётчик токенов вместо «символы ÷ 4»

**Проблема.** Оценка «символы ÷ 4» ошибается на 47% для фактов, на 52% для JSON и на 17% для прозы (`docs/PILOT.md`, `results/pilot/token_counter_fit.json`). Лимит контекста «2 000» означал бы 1 000–4 000 реальных токенов в зависимости от типа текста, и системы получали бы неодинаковый бюджет.

**Решение.** Лимит 2 000 измеряется офлайн-счётчиком, откалиброванным по `usage`. Счётчик детерминирован, работает без сети и состоит из линейной модели по признакам регулярных выражений:

```text
words        = число слов [A-Za-z]+(?:'[a-z]+)?              вес 1.187
chars_over_6 = сумма max(0, len(слово) - 6) по словам         вес 0.658
caps_chars   = число букв в словах из заглавных (len > 1)     вес 0.845
digit_chars  = число цифр в числах \d+                         вес 0.500
punct        = число символов, не буквы, не цифры, не пробелы вес 1.300
digit_runs, newlines                                          вес 0 (отброшены подгонкой)
tokens       = округление суммы вес × признак
```

Точные веса — в `results/pilot/token_counter_fit.json`. Подгонка по 32 текстам (4 типа: факты, проза, JSON, смешанный; размеры 600–6000 символов), проверка по 32 другим. Ошибка на проверке: средняя 0,4–2,4%, максимум 6,3% (цель была не больше 15%).

**Реализация.** Модуль счётчика пишется на Шаге 3 на чистом Python (без numpy) и проверяется на образцах из `results/pilot/calibration_samples.jsonl` как на независимом источнике ожидаемых значений.

**Проверка вне выборки.** Тексты будущего генератора устроены иначе. Раннер сохраняет для каждого вызова фактический размер контекста в токенах (из `usage`) рядом с посчитанным счётчиком. На Smoke расхождение сверяется; если оно превышает 15%, счётчик калибруется заново до заморозки бенчмарка.

**Смысл лимита.** 2 000 посчитанных токенов приблизительно равны 2 000 реальным токенам памяти для всех систем, кроме `full_history`. Проверено вызовом с контекстом 1 999 посчитанных токенов: 2 678 входных токенов всего, из них 556 служебных и около 120 задача и роль.

## D5. Отказы провайдера — отдельный исход

На синтетической «словесной каше» провайдер вернул `API Error: Haiku 5.5 can't help with this` в 12 из 49 вызовов, выход 0 токенов, `is_error=true`. CLI сам повторяет запрос, и входные токены в `usage` считаются дважды. На естественном тексте отказов нет (0 из 197).

Решение: отказ — не ошибка инфраструктуры и не ошибка модели в обычном смысле. Раннер:
- распознаёт отказ по тексту результата или по нулевому выходу при `is_error`;
- пишет его в трассу с типом `refusal` и сохраняет `usage`;
- повторяет вызов один раз; если отказ повторился, агент считается не выполнившим действие, метка провала `agent`, причина `refusal`;
- считает отказы отдельной строкой в отчёте. Особое внимание — категории C5.

## D6. Рабочее число потоков — 8

Замер на реалистичном вызове: 9,0 / 35,1 / 64,0 вызова в минуту при 1 / 4 / 8 потоках, без ошибок (`results/pilot/parallel.jsonl`). Раннер по умолчанию использует 8 потоков и снижает число потоков при ошибках лимитов. Больше 8 потоков не проверялось.

## D7. `--bare` не используется

Без `ANTHROPIC_API_KEY` режим `--bare` не авторизуется, а с ключом он не проверялся (NOT RUN). Чтобы вызовы выглядели одинаково при любой авторизации, во всех режимах используется один набор флагов без `--bare` (`docs/PILOT.md`).

## D8. Что остаётся непроверенным после пилота

Приоритет переменных при одновременно заданных ключе и токене подписки, оплата по ключу и по подписке, запуск в Docker, больше 8 потоков, Agent SDK (накладные токены малы, поэтому не потребовался). Статусы — в `docs/PILOT.md`.

## D9. Прогноз стоимости: вариант B предварительно

По измеренной стоимости вызова $0,00053–0,00066 вариант A вместе с полным проходом извлечения даёт $8,9–11,1 плюс рост `full_history`; вариант B — $7,5–9,3 (`docs/PILOT.md`). По правилу раздела «Уровни прогонов» предварительно выбирается вариант B. Окончательное решение принимается после Smoke по фактической стоимости и по стоимости вызовов извлечения.
